# ReelDock · 影坞：分阶段开发计划

日期：2026-10-08。前置约定：Kodi 优先；已有有效外挂字幕不限语言。

以下按一个熟悉 Python / React 的开发者全职投入估算，约 22 个工作日，另留 20% 集成缓冲，整体约 5–6 周。是工作量估计而非交付承诺；P0 的实际存储能力、媒体探测和网络结果决定是否调整。

## 阶段总览

| 阶段 | 参考工作量 | 主要交付 | 完成门槛 |
| --- | --- | --- | --- |
| P0 风险验证 | 2 天 | WebDAV / Range / MOVE / 射手 / Kodi 验证记录，样本矩阵 | 找到一条可用的实际环境路径，列明不可支持情况 |
| P1 工程基础 | 3 天 | 前后端骨架、数据库、任务执行、设置页、开发容器 | 配置能保存，连接能测试，任务中断可恢复 |
| P2 电影刮削 | 5 天 | 电影识别、TMDB、Kodi NFO、图片和演员、上传校验、状态页 | 单片从扫描到产物远程验证可用；此阶段自动归档仍关闭 |
| P3 字幕与安全归档 | 4 天 | 音轨 / 字幕判定、射手下载、成功门禁、移动恢复 | 必需资产缺一不可，验证通过才归档，故障不会误删覆盖 |
| P4 电视剧与完整 UI | 5 天 | 剧 / 季 / 集处理、继承资产、批量操作、局部重试 | 包内某集失败阻塞整包，电影及剧集都能完成端到端闭环 |
| P5 NAS 发布验收 | 3 天 | 正式 Compose、镜像流水线、备份升级文档、v0.1.0 | 实际飞牛 + OpenList + Kodi 验收通过 |

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5。P0 失败时保留已完成的验证工具，先解决基础能力，不以 UI 完成代替后端闭环。

## P0：先验证实际约束

### 工作项

- 获取实际 OpenList 版本、存储驱动、同一后端的测试输入 / 输出路径。
- 测试 PROPFIND 的文件名编码与逐项返回状态，验证 PUT、读回、临时文件发布和目录 MOVE。
- 用非片源的专用测试目录验证 MOVE：中文路径、目标重名、源不稳定、超时、权限不足、部分失败。
- 验证后端移动是否即时完成、是否存在延迟可见性、是否内部启动异步复制；记录可支持的语义。
- 比较本地文件与 WebDAV Range 的四块射手哈希，验证重定向、Content-Range、无 Range 与错误长度的处理。
- FFprobe 对 MKV、MP4、索引在尾部的文件远程探测，测量流量、时延和预算失败行为。
- 在 NAS 网络查询 / 下载射手字幕，统计少量代表性媒体的命中及格式；没有命中不能认定集成成功。
- 使用指定版本 Kodi 导入 NFO 与 `.actors`，覆盖首次入库、刷新及播放器外网断开。
- 定版目录包规则、字幕判定证据、演员范围与缺图策略。

### 交付与验收

输出 `docs/compatibility.md` 和可重复运行的探测工具；所有写入验证仅操作专用测试目录。给出当前驱动支持 / 不支持列表、片段读取预算建议和已测 Kodi 版本。

**已有进展：** 本机通过公开开源项目的测试哈希获取了 3 个射手 ASS 候选，并下载解析了一份。它仅证明该样本在本机当时可用，尚未完成本阶段的 NAS / WebDAV / Kodi 验证。

## P1：建立可恢复的工程基础

### 工作项

- 后端项目、前端项目、格式检查、依赖锁文件、基础 CI。
- 领域模型与 Storage / Metadata / Subtitle Provider 接口。
- SQLite 表结构及 Alembic 迁移；任务 / 事件 / 阶段检查点。
- Worker 领取、租约、心跳、幂等键、启动恢复和暂停队列。
- WebDAV 客户端的超时、错误分类、凭证与重定向策略。
- 配置页、连接检查、管理员登录、健康检查、结构化脱敏日志。
- 开发用 Docker 构建及本地 Mock WebDAV 环境。

### 验收

刷新页面及重启容器后配置、任务和错误信息不丢失；重复提交同一任务不会并发操作同一包。没有凭证、连接失败和权限不足有可理解提示。

## P2：完成电影资产链路

### 工作项

- 增量扫描、稳定窗口、过滤下载中和示例文件。
- 文件名解析、TMDB 候选评分、手动选择 / 指定 ID。
- 中文信息优先与字段级回退；图片语言候选回退。
- Kodi 电影 NFO、海报、背景图、演员头像导出。
- 默认演员前 20 位中来源有图者必需，无图明确标记；支持全部演员与严格模式。
- 暂存生成、内容验证、WebDAV 上传与完整小文件读回哈希。
- 现存 NFO / 图片检测与保护，清单导出。
- 电影表格、状态列、详情、NFO / 图片预览和人工补图。

### 验收

能处理已有 NFO、错误年份、同名电影、中文无图片回退等情况。只在有明确 ID / 可靠匹配时生成产物，任何必需图片失败都有明确状态。

**此阶段只交付资产链路。自动目录归档须待 P3 字幕和恢复门禁完成后开启。**

## P3：字幕门禁与安全归档

### 工作项

- 内部 Range 网关、FFprobe 子进程超时和读取预算。
- 默认音轨语言归一化、字幕轨标签和完整 / forced 判定。
- 外挂字幕关联、格式 / 时间轴校验，支持已有任意语言外挂。
- 射手 Provider、四块哈希、候选下载、字幕编码和延时处理。
- 字幕证据不明的人工确认与手动补齐流程。
- required asset set、最终成功谓词、目录快照复核。
- MOVE 意图持久化、Overwrite: F、Multi-Status 解析、源目标核对。
- 中断恢复、局部重试、归档冲突及 `move_unknown` 处理。

### 验收

完整覆盖 [字幕判定矩阵](acceptance.md)及移动故障注入；强制终止应用后不会因数据库状态滞后重复覆盖目标。必须下载字幕却无结果时，电影保持在待刮削目录。

## P4：电视剧与 tMM 风格管理

### 工作项

- 剧 / 季 / 集模型与 TMDB 元数据，支持常规 `S01E01`、中文季集命名及 Specials。
- 季集号不明确、多集单文件等结构进入待确认；多集导出能力按 Kodi 实测结果决定首版支持范围。
- 剧级 NFO / 海报 / 背景图 / 演员、集级 NFO；季海报与单集缩略图等增强项独立显示。
- 每集字幕判定、上传和验证；共享资产去重。
- 归档单位为当前稳定的剧集包，任一集失败阻塞整包；目标已有剧目录时 V1 明确拒绝自动合并。
- 目录树、剧集展开、筛选缺失项、批量刮削和失败步骤重试。
- SSE 进度、字幕预览、阻塞原因、归档历史、事件断线恢复。

### 验收

一季多集样本中，缺字幕的单集有准确标识；补齐后重试只补失败项，全部通过才移动。无需等待 TMDB 上未存在于当前包的其它集数。

## P5：飞牛 Docker 发布

### 工作项

- 正式多阶段镜像、非 root 运行、UID/GID、健康检查、日志轮转与优雅退出。
- GHCR 固定版本镜像，先验收 amd64；按设备需求和 CI 结果提供 arm64。
- Compose 示例、初次配置、OpenList 权限说明、代理与 NAS 网络排查。
- SQLite 备份 / 恢复、密钥备份、升级 / 迁移 / 回退说明。
- 飞牛真实存储与 Kodi 兼容性回归，包含断网、重启、目标冲突与已有数据。
- 清理发布包中的本地配置、凭证、用户路径和样本素材；增加 TMDB 关于页标识。

### 验收

在实际飞牛 NAS 通过 Compose 部署，浏览器完成电影和电视剧全链路。Kodi 从归档目录读取 NFO、海报、背景图、字幕和演员头像，播放端不必访问 TMDB。重启后任务继续，升级与备份恢复路径可重复验证。

发布 v0.1.0，并公布实测环境及尚不支持的目录 / 媒体类型。

## 后续迭代

- v0.2：电视剧增量季集的安全合并、失败恢复工具、自动补刮与更完善的匹配规则。
- v0.3：新增元数据 / 字幕 Provider；Emby、Jellyfin、Infuse 导出配置与 NAS 图片服务。
- 需求明确后：多媒体库、多 WebDAV 连接、外部完成事件 / Webhook、严格字幕匹配、原盘结构、多人管理。

不能用额外 Provider 的实现替代本期 TMDB / 射手目标；接口先预留，实现按版本推进。

## GitHub 管理约定

公开仓库 `gteall/reeldock` 管理应用源代码、设计文档、依赖锁文件和部署模板。开发按 P0–P5 建里程碑，工作项用 Issue 追踪；常规修改从短期分支提交 PR，合并前通过与改动相关的检查。版本使用 `v0.x.y` 标签，并对应相同的 GHCR 镜像标签。

当前初始化只提交方案文档及忽略规则；源码骨架、CI、Issues 和里程碑在对应阶段建立。本计划没有宣称已发布应用或已创建远程开发任务。
