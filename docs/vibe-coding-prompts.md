# ReelDock · 影坞：分阶段 vibe coding 提示词

适用于本仓库的 P0–P5 开发。已包含最新规则：先 TMDB 匹配、先完成基础 NFO / 图片 / 演员资产，字幕后置；TMDB 中文作品跳过音轨 / 字幕探测。

## 使用方法

在仓库根目录启动编码助手，按 P0 → P1 → P2 → P3 → P4 → P5 依次发送对应代码块。首次会话或新会话先发送“公共约束”，再发送当前阶段。不要一次发完六个阶段；每阶段以实际可验证的交付和进度记录作为下一阶段输入。

阶段提示词要求编码助手实施工作，本次编写提示词并不代表这些阶段已经执行。实际进度见 [开发进度](progress.md)。

## 公共约束：首次 / 新会话先发送

```text
你正在当前仓库开发 ReelDock（中文名：影坞）。请先读取适用的 AGENTS.md、README.md、docs/architecture.md、docs/roadmap.md、docs/acceptance.md、docs/progress.md，以及本次阶段提示词；检查 git status 和已有代码，再接着现有实现工作。

技术栈：Python 3.12 + FastAPI + Pydantic + HTTPX；SQLite WAL + SQLAlchemy 2 + Alembic；React + TypeScript + Vite + Ant Design + TanStack Query；REST + SSE；FFprobe / FFmpeg；uv / pnpm；Docker Compose。采用模块化单体，单应用容器、单 Uvicorn 进程、持久化 Worker；不要无必要地引入 Redis、独立微服务或改换技术栈。

产品硬性规则：
1. 首要播放端 Kodi；元数据仅 TMDB，自动字幕仅射手，分别通过独立 Provider 接口封装。片源和刮削产物保存在 OpenList WebDAV，本地只保存配置、SQLite、日志和缓存。
2. 正式处理顺序是：扫描及等待稳定 → 匹配 TMDB → 获取和生成基础 NFO / 海报 / 背景图 / 演员头像 → 上传并读回验证所有基础必需资产 → 字幕阶段 → 最终 manifest 上传验证 → 安全归档。
3. 以媒体包为单位，任何基础必需资产未远程验证，不允许触发任何视频探测、视频内容 Range 读取、射手哈希或射手请求。字幕和最终 manifest 不属于这个基础前置集合，避免循环依赖。
4. 字幕阶段首先读取 TMDB 详情的 original_language；电影用电影字段，电视剧各集继承剧级字段。中文集合集中配置，默认 {zh, cn}。命中中文则状态 skipped_tmdb_chinese，直接满足字幕策略；不得调用 FFprobe / FFmpeg，不读视频分块，不抽取字幕，不请求射手，也不为了 NFO 媒体参数或 UI 信息绕过跳过规则。
5. 请求参数 language=zh-CN 只影响返回文本，不能用于语言分类；中文标题、制片国家或 spoken_languages 中存在中文也不能替代 original_language。TMDB 语言缺失 / 无法识别时 needs_review，不默认豁免。
6. 仅 TMDB 明确非中文的作品进入实际音轨 / 字幕探测。实际默认音轨中文，或有完整有效内置简体字幕，或有有效且匹配的外挂字幕，均不必下载；已有外挂字幕不限语言。三者都不满足时必须从射手补齐有效外挂，上传和验证成功才能归档。证据冲突或音轨语言不明需待确认。
7. 基础 NFO 不依赖媒体探测，未知的可选 fileinfo/streamdetails 省略，不伪造音轨、编码、时长。中文规则只是业务分类，不表示文件实际音轨已经检测为中文。
8. Kodi 演员头像随媒体保存到 .actors/演员名.jpg，不默认写 TMDB 远程头像 URL。按已有演员策略区分来源无图与下载失败。
9. 所有必需项成功并远程验证、源快照稳定且目标不冲突后才能移动整个包。服务器端 MOVE 必须 Overwrite: F，解析 207 子项失败，移动前持久化意图，超时 / 重启后核对源目标。禁止自动改为整视频下载上传删除，禁止盲删源或覆盖目标。
10. 配置、阶段状态、资产状态、幂等键、租约、错误及归档意图都持久化。字幕失败重试复用已验证基础资产；源文件、TMDB ID、语言或策略变化时重新评估相应检查点。

工作方式：
- 实际实施本次阶段，合理拆成小步；先检查现有实现，避免重写已完成的模块。常规可逆的实现选择自行决定。
- 只推进当前阶段及其必要依赖；完成后记录交接，不提前执行下一阶段或发布版本。
- 缺少外部凭证 / NAS / Kodi 时，继续实现 Mock、自动化测试和可重复运行的验证工具；真实联调明确标为未验证，不能假装完成。
- 对关键业务顺序、条件分支、远程写入和恢复逻辑提供有价值的测试；执行与改动相关的检查，修复失败。不要用硬编码成功或静态假数据替代实际接口。
- 不提交凭证、片源、下载字幕、签名 URL 或个人 NAS 地址。保留用户已有修改；真实写入验证仅操作约定的测试目录。
- 在 docs/progress.md 记录当前阶段、实现内容、运行命令及结果、真实 / Mock 验证范围、剩余问题和下一步。提交当前阶段前检查差异和敏感信息；若已处于用户开发分支，使用该分支，不擅自切换或覆盖。
- 最终说明实际改动、验证证据、未完成 / 未验证项及后续入口，不仅返回计划。
```

## P0：外部能力验证与兼容性边界

```text
请遵守公共约束，实施 ReelDock P0：建立可重复运行的验证工具，验证 OpenList WebDAV、远程媒体读取、射手 API 和 Kodi 的可行性，记录兼容性边界。

先检查已有调研记录，复用公开样本验证结果，不把它当作实际 NAS 已通过。读取 docs/research.md 和 docs/acceptance.md。

需要实际完成：
1. 在 scripts/ 下实现配置驱动的验证工具，敏感配置从环境变量 / 本地忽略文件读取，输出机器可读结果及简短说明。可使用 Python 标准库，必要依赖锁定。
2. WebDAV 检查 PROPFIND Depth:1、Unicode / 空格 / # / % 路径、逐项状态、stat、PUT 小文件及完整读回校验。写入 / MOVE 验证仅使用独立测试目录，覆盖目标已存在、权限错误、部分失败及超时后核对。
3. 对受控测试媒体验证 206 / Content-Range、302、短读、错误范围以及 Range 被忽略返回 200；不得意外下载整部视频。比较本地文件与四个 4KiB 远程块的射手指纹。
4. 建立 MKV / MP4、尾部索引、中文 / 外语音轨、简繁 / forced 字幕等样本矩阵，记录 FFprobe 的实际流量、时延和预算。这里是专用能力测试，不得把探测变成正式刮削的前置步骤。
5. 从射手完成可重复的候选查询及下载校验，记录有匹配 / 无匹配 / 网络失败；不把第三方响应正文或字幕内容提交到 Git。
6. 建立 Kodi 导入样例生成器或步骤，验证基础 NFO 不含 streamdetails 时仍能入库、.actors 可用，以及首次导入 / 刷新 / 播放端断网。真实 Kodi 不可用时保留待验清单。
7. 更新 docs/compatibility.md 与 docs/progress.md，逐项区分实测通过、Mock 通过、未验证及不支持。

验收：工具可重复运行且有正确失败退出 / 未验证状态；中文 / 非中文的正式流程规则未被改变。缺真实环境时完成离线工具与测试，明确剩余外部依赖，不能将 P0 标为全部完成。
```

## P1：工程骨架、数据库与持久化任务

```text
请遵守公共约束，读取 P0 进度并实施 ReelDock P1：搭建真正可运行的工程基础，暂不实现完整刮削及归档。

建议结构 backend/src/reeldock、frontend/src、scripts、tests，具体随现有代码调整；不要重建已有项目。

需要实际完成：
1. Python / FastAPI 后端、React / TypeScript 前端、uv / pnpm 锁文件、开发容器和相关 CI；提供本地启动步骤与健康检查。
2. 定义 StorageProvider、MetadataProvider、SubtitleProvider 接口及领域模型；实现基础 WebDAV 客户端的连接、列表、错误分类、超时、代理和重定向策略，复用 P0 结论。
3. SQLite / Alembic 模型覆盖配置、包、媒体、资产、任务步骤、事件和归档意图；保留 TMDB original_language、基础资产状态及字幕判定原因。数据库在本地文件系统。
4. Worker 实现持久化领取、包级租约 / 心跳、幂等、防止同包并发、检查点、局部重试、暂停及重启恢复。建立 base_assets_verified → subtitle_policy → final_manifest → archive 的阶段约束，不能先执行探测。
5. 实现服务端凭证保护、脱敏日志、管理员登录及修改操作来源校验。设置页可保存 WebDAV 地址、输入 / 输出路径、TMDB 凭证及预算；拒绝相同 / 互相包含的路径。
6. REST 提供配置、连接检查、任务列表及状态；建立可恢复的事件接口，为 SSE 留出实现入口。外部调用全部经过 Provider。
7. 加入必要测试，覆盖配置持久化、无效路径、任务重复提交、竞争领取和重启恢复，完成前后端构建。

验收：本地 / 开发容器能启动，刷新和重启不丢配置 / 任务，同包不被重复执行；真实连接未验证的部分准确标记。当前阶段不移动任何实际媒体。更新开发步骤与 docs/progress.md。
```

## P2：电影 TMDB 与基础资产闭环

```text
请遵守公共约束，实施 ReelDock P2：完成电影从发现、TMDB 匹配到基础 NFO / 图片 / 演员资产上传验证的闭环。本阶段不运行音轨 / 字幕探测、射手请求或自动归档。

需要实际完成：
1. WebDAV 增量扫描、稳定窗口、下载中文件过滤和独立媒体包识别；只登记文件信息，不读视频内容。
2. 从文件名 / 已有 NFO 的明确 ID 优先匹配 TMDB；否则解析标题 / 年份、展示候选与置信度，支持人工指定 ID。低置信度不静默选择第一个。
3. 实现 TMDB MetadataProvider：电影详情、演职员、图片、configuration、缓存、429 重试与字段级中文回退。持久化真实 original_language，与请求 language=zh-CN 分离。
4. 生成 Kodi UTF-8 电影 NFO、poster.jpg、fanart.jpg、.actors 图片。NFO 不依赖 FFprobe，未知 streamdetails 省略。保留已有用户内容和观看进度，处理 ID 冲突及备份。
5. 依演员策略处理来源无图 / 有图下载失败，校验 XML 和图片实际内容。通过统一资产上传器上传并完整读回比对 SHA-256，支持重启续做和已有资产复用。
6. 包内所有基础必需资产远程验证后才标记 base_assets_verified。最终 manifest 和条件性字幕不纳入这个前置集合。
7. 前端提供电影列表、匹配选择、基础资产状态、NFO / 图片预览、错误原因和失败项重试。此时字幕显示尚未进入字幕阶段。
8. 测试同名年份冲突、中文文本 / 图片回退、坏图片、PUT 后内容不一致、原 NFO 保护，以及任何失败情况下探测和字幕 Provider 调用次数为零。至少完成 Mock 全链路，有配置时在专用 WebDAV 测试目录验证实际上传。

验收：一部电影能生成并远程验证基础资产；重试不会重新抓取已完成项；扫描到基础完成全过程零视频内容读取、零 FFprobe / FFmpeg、零射手调用，自动归档关闭。更新 docs/progress.md。
```

```text
请遵守公共约束，实施 ReelDock P3：在已有基础资产闭环之后加入 TMDB 语言分流、字幕处理、最终清单和安全目录归档。不要改成先探测媒体再匹配 TMDB。

8. 前端显示 TMDB 语言、实际探测结果、跳过原因、字幕和归档状态。中文的实际音轨显示未探测，不能伪装成已探测中文或字幕已下载。
9. 完整覆盖 docs/acceptance.md 的执行顺序、字幕矩阵、上传和移动故障。记录 Provider 调用顺序，证明所有基础资产读回完成先于首次探测；断言中文分支及基础失败分支的禁止调用次数为零。

验收：中文电影不读视频内容即可通过字幕策略；外国电影按实际轨道 / 字幕决定是否补下载；任一必需项失败不归档；重试与重启能复用基础资产。真实归档只在测试目录联调，未提供实际后端时明确标记未验证。更新 docs/progress.md。
```

## P5：Docker、飞牛与 Kodi 发布验收

```text
请遵守公共约束，实施 ReelDock P5：完成可交付的 Docker 部署、飞牛 NAS 和 Kodi 验收，准备 v0.1.0 发布材料。
```
